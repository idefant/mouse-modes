# Сборка и разработка

Нужны Node.js 22.12+ и Rust stable. На Windows установите Visual Studio C++ Build Tools и WebView2. На Linux нужны заголовки GTK3, WebKitGTK 4.1, AppIndicator и OpenSSL, а для запуска — polkit и `uinput`.

Зависимости Arch/Omarchy: `webkit2gtk-4.1 libappindicator-gtk3 openssl polkit`. Зависимости Ubuntu приведены в [CI](.github/workflows/check.yml).

```sh
npm ci
npm run tauri dev
```

Автономная сборка с встроенным интерфейсом:

```sh
npm run tauri build -- --no-bundle
```

Исполняемый файл будет в `src-tauri/target/release/`. Для локальной debug-сборки добавьте `--debug`.

Установщик для текущей ОС:

```sh
npm run tauri build -- --bundles deb      # Linux
npm run tauri build -- --bundles nsis     # Windows
```

## Проверки

```sh
npm run check
npm test
cargo test --manifest-path src-tauri/Cargo.toml
```

CI проверяет Linux и Windows отдельно. Проверки на одной ОС не заменяют живую проверку другой.

## Linux: обработка ввода

Нативный Rust-обработчик запускается тем же исполняемым файлом с `--input-helper` до инициализации интерфейса. GUI вызывает его через polkit и передаёт только настройки и команды записи по унаследованным pipe. Данные произвольных нажатий не отправляются в интерфейс и не сохраняются.

Обнаружение устройств и создание виртуальных устройств выполняются вне потока обработки движения. При пустых назначениях мышь использует обычный путь системы. С назначениями сохраняется непрерывный relay, чтобы нажатие хоткея во время перетаскивания не теряло состояние кнопок. Отдельные клавиатурные устройства захватываются только на время записи; комбинированные устройства клавиатуры и мыши сохраняют общий relay при назначенных хоткеях. Поддерживаются составные HID-клавиатуры с непозиционными абсолютными осями, например громкостью.


Дополнительные нативные проверки Linux работают с искусственными устройствами, не захватывая физические устройства пользователя. Они проверяют запись сочетаний, составные HID, перетаскивание и поток движения 1 кГц при медленном обнаружении подключённого устройства. Такие проверки помечены `#[ignore]` и требуют доступа администратора к `uinput`.

Сначала соберите тесты обычным пользователем:

```sh
cargo test --manifest-path src-tauri/Cargo.toml --lib --no-run
```

Затем запустите указанный Cargo тестовый исполняемый файл с правами администратора и аргументами:

```text
platform::linux_native::native_tests --ignored --nocapture --test-threads=1
```

Синтетические F13–F17 и модификаторы вне записи видны рабочему столу; запускайте проверки без параллельного использования клавиатуры.

## Выпуск версии

CI проверяет интерфейс и Rust-код и собирает приложение на Linux и Windows.
Пайплайн [Release](.github/workflows/release.yml) запускается при push тега `v<semver>`.

1. Добавьте в `CHANGELOG.md` непустую секцию `## [X.Y.Z] - YYYY-MM-DD` с изменениями этой версии.
2. Выполните `node scripts/set-version.mjs X.Y.Z` (допускаются предварительные версии, например `0.1.0-alpha-1`) и закоммитьте изменения вместе с CHANGELOG.
3. Создайте тег `git tag -a vX.Y.Z -m "Release X.Y.Z"` и отправьте коммит и тег в GitHub.

Версия сборки всегда берётся из тега и синхронизируется в npm, Cargo, обоих lock-файлах и конфигурации Tauri. Без соответствующей записи CHANGELOG выпуск завершается ошибкой. Только после успешных проверок и сборки обеих ОС публикуется релиз с установщиками `.exe` (NSIS), `.deb`, `.rpm` и контрольными суммами SHA-256. В описание попадает только текст секции текущей версии. Теги с суффиксом отмечаются как prerelease, стабильные версии — как latest. Для prerelease публикуются `.exe` и `.deb`: упаковщик RPM в Tauri не принимает версии с дефисом, поэтому `.rpm` выпускается только для стабильных версий.

Для повторного запуска выберите существующий тег в ручном запуске Release; запуск с ветки отклоняется. После предварительного выпуска убедитесь, что сборка и публикация завершились успешно, прежде чем создавать стабильную версию. Каждая версия, включая предварительную, требует своей записи CHANGELOG.
