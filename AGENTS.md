# Repository Guidelines

## Структура проекта

Mouse Modes — приложение для Windows и Linux на Tauri 2, React 19, TypeScript и Rust. Оно преобразует движение мыши при удержании горячих клавиш.

- `src/` — интерфейс, SCSS-модули, схемы настроек Zod и логика записи сочетаний; тесты расположены рядом с кодом.
- `src-tauri/src/engine.rs` — общая модель настроек и движок; `platform/` — реализация ввода для каждой ОС; `lib.rs` — интеграция с Tauri.
- `src-tauri/icons/` — значки приложения; `src-tauri/linux/` — службы systemd, правила устройств и установочные скрипты.
- `scripts/` — управление версиями, тесты релизных утилит и проверки Linux-пакетов.
- `.github/workflows/` — проверки, сборка и публикация релизов. Подробности разработки см. в `CONTRIBUTING.md`.

## Сборка и локальная разработка

Нужны Node.js 22.12+ и Rust stable; CI использует Node.js 24. Системные зависимости для каждой ОС перечислены в `CONTRIBUTING.md`.

- `npm ci` — установить зависимости по lock-файлу.
- `npm run tauri dev` — запустить приложение в режиме разработки.
- `npm run dev` — запустить только Vite на `127.0.0.1:1420`.
- `npm run build` — проверить TypeScript и собрать интерфейс в `dist/`.
- `npm run tauri build -- --no-bundle` — собрать приложение в `src-tauri/target/release/`.
- `npm run check` — выполнить проверку типов, ESLint и Stylelint.
- `npm run format` — отформатировать интерфейс и конфигурацию через Prettier.

## Стиль кода и именование

Используйте отступы в два пробела в TypeScript/SCSS и четыре в Rust. Сохраняйте двойные кавычки и точки с запятой в TypeScript. Компоненты и типы называйте в `PascalCase`, функции и переменные TypeScript — в `camelCase`, функции и модули Rust — в `snake_case`. Для стилей компонентов используйте `*.module.scss`. Согласовывайте контракты настроек Rust и схемы Zod.

## Тестирование

Запускайте `npm test` (Vitest, `src/*.test.ts`), `npm run test:release` (Node.js, `scripts/*.tests.mjs`) и `cargo test --locked --manifest-path src-tauri/Cargo.toml`. Числовой порог покрытия не установлен. Добавляйте проверки изменённого поведения, особенно записи сочетаний и освобождения устройств. Проверяйте платформенные изменения на соответствующей ОС. Нативные тесты с `#[ignore]` запускайте отдельно по инструкции в `CONTRIBUTING.md`: они генерируют системный ввод.

## Коммиты и pull request

История использует сообщения вида `fix(windows): restore hotkey capture`, а также префиксы `feat:`, `refactor:`, `test:`, `docs:`, `ci:` и `release:`. Следуйте этому формату, указывая область при необходимости.

В pull request опишите проблему, изменение поведения, затронутые ОС и выполненные проверки. При наличии задачи добавьте ссылку; для изменений интерфейса приложите скриншоты. При подготовке релиза обновляйте `CHANGELOG.md` и синхронизируйте версии командой `node scripts/set-version.mjs X.Y.Z`.
